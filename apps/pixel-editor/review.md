# Review 결과: 픽셀 아트 에디터

검토 기준: `spec.md` 전체, 11장 체크리스트("Embed 후" 제외). 내장 브라우저에서 `http://localhost:8000/apps/pixel-editor/`를 직접 열어 시험했다. 뷰포트는 320, 375, 820, 1000, 1280px을 썼고 라이트와 다크를 모두 봤다.

## 1. 결론

**수정 필요**

기능, 기록, 복원, PNG는 시험한 범위에서 모두 맞다. 다만 창 크기에 따라 격자 크기가 매 프레임 바뀌며 멈추지 않는 문제가 실제로 재현되어 체크리스트 한 항목이 실패한다.

### 검토 후 수정 기록

- 중요 1: `html`에 `scrollbar-gutter: stable`을 추가했다.
- 사소 2: 창 `resize`에서도 `fitCanvas`를 호출하게 했고 `spec.md` 5장에 반영했다.
- 사소 3: 받침에 따라 `로`/`으로`를 고르게 했다.
- 사소 4, 5, 6: 실제 키보드 사용과 동작에 영향이 없어 그대로 두었다.

## 2. 문제 목록

치명: 없음

### 중요

**1. 세로 스크롤바가 생기는 경계 높이에서 격자 크기가 끝없이 바뀐다**

- 조건: 폭 768px 미만(2단 구성으로 바뀌기 전), 자리를 차지하는 스크롤바(Windows 데스크톱 기본, 15px), 특정 창 높이.
- 재현: `devicePixelRatio` 1.5에서 앱을 폭 600px, 높이 1023px iframe으로 연다. `canvas.width`를 4초 동안 관찰하면 816과 848을 오가며 241프레임 중 240번 바뀐다. 같은 시간에 `window`의 `error` 이벤트(`ResizeObserver loop completed with undelivered notifications.`)가 284번 났다. 높이를 1px씩 바꾼 시험에서는 1021~1025px에서 나타났다.
- 원인: 스크롤바가 생기면 `#grid-wrap` 폭이 줄고, `fitCanvas`가 칸 크기를 줄이면 페이지가 짧아져 스크롤바가 사라지고, 다시 폭이 늘어나는 순환이다.
- 영향: 격자가 깜빡이고 다시 그리기가 계속 돈다. 그리는 중이면 칸이 손 아래에서 계속 바뀐다.
- 파일: `ui.js:178-188`(`fitCanvas`), `ui.js:509`(`ResizeObserver`)
- 제안: `html`에 `scrollbar-gutter: stable`을 준다. 같은 iframe에 이 규칙만 넣었을 때 3초 동안 크기 변화가 0번이었다(단, 이 구간은 프레임이 3개뿐이라 참고용이다). 수정 후 같은 조건으로 다시 재야 한다.

### 사소

**2. 폭 변화 없이 `devicePixelRatio`만 바뀌면 캔버스를 다시 맞추지 않는다**

- 재현: 시험 중 `devicePixelRatio`가 1에서 1.5로 바뀌었을 때 `canvas.width`는 432, CSS 폭은 432px 그대로였고, 새로고침하자 640과 426.667px이 되었다. 정수 배가 아니므로 5장의 "선이 흐려지지 않는다"가 깨진다. 좌표 계산은 CSS 크기 기준이라 어긋나지 않는다.
- 파일: `ui.js:179`, `ui.js:509`
- 제안: `matchMedia('(resolution: ...dppx)')` 변경 또는 `window`의 `resize`에서도 `fitCanvas`를 호출한다. 브라우저 확대·축소와 모니터 이동에서도 생길 수 있다(이 두 경우는 직접 해 보지 않았다).

**3. 낭독 문구의 조사가 틀린다**

- 재현: 색을 고르고 Space를 누른 뒤 `#live`를 읽었다. `종이으로`, `풀으로`, `하늘으로`, `바다으로`, `보라으로 칠함`이 나왔다.
- 파일: `ui.js:220`
- 제안: 받침에 따라 `로`/`으로`를 고르거나(ㄹ 받침은 `로`), 팔레트와 무관한 문구로 바꾼다.

**4. Shift를 뗀 `keyup`을 못 받으면 키보드 획이 끝나지 않는다**

- 재현: 도구의 키 입력(`shift+Right`)은 Shift 자체의 keydown/keyup 없이 수식자만 보낸다. 이후 `]`, `E`, Ctrl+Z, Ctrl+Y가 모두 무시되었고, Shift 없는 방향키를 누르자 풀렸다. 실제 키보드에서 Shift를 떼면 정상이고(합성 `keyup` 시험 통과), 포커스를 잃어도 끝난다(시험 통과). 실사용 영향은 작다.
- 파일: `ui.js:369-375`, `ui.js:427-429`
- 제안: 키 입력 때 `event.shiftKey`가 false이면 `finishKeyboardStroke`를 먼저 호출한다.

**5. 인라인 테마 스크립트가 코드 규칙과 다르다**

- `function`과 `var`를 쓴다(화살표 함수, `const`/`let` 규칙). 블로그 `index.html`의 같은 스크립트와 같은 형태이고 동작 문제는 없다.
- 파일: `index.html:12-14`
- 제안: 규칙에 맞춰 바꾸거나 예외로 둔다.

**6. spec.md에 없는 작은 추가**

- `NumpadEnter`도 칠하기로 처리한다(`ui.js:414`).
- `index.html:7`의 `description`, `index.html:9`의 파비콘.
- 동작에 해가 없어 그대로 두어도 된다. 레이어, 애니메이션, 격자 크기 변경, 파일 불러오기, 채우기는 없다.

### 코드 검토에서 문제가 없던 항목

- `innerHTML` 사용 없음, 전역 변수 없음(`window`에 앱 변수 없음을 확인).
- 하드코딩 색상: `style.css`의 hex와 `rgba`는 36개 모두 `:root` 세 벌 안에 있고, 컴포넌트에는 없다. JS의 색은 `PALETTE`뿐이다.
- `/`로 시작하는 경로 없음.
- ES 모듈, `const`/`let`, 화살표 함수, 들여쓰기 2칸, 세미콜론, 작은따옴표, 한국어 주석 준수(`index.html` 인라인 제외, 큰따옴표는 `ui.js:55`의 CSS 선택자 안뿐).
- 칸 좌표는 `getBoundingClientRect` 기준이고, 창 크기를 바꾼 뒤의 실제 클릭도 정확했다.
- 획 진행 중 `pointercancel`, `lostpointercapture`, 포커스 상실, 창 크기 변경에서 상태가 어긋나지 않았다.

## 4. 확인하지 못한 것과 그 이유

- **실제 터치 입력**: 내장 브라우저의 클릭은 마우스로 전달된다. 스크롤 방지와 길게 누르기는 실기기에서 봐야 한다.
- **`prefers-reduced-motion` 실제 적용**: 이 조건을 흉내 낼 수단이 없다.
- **`devicePixelRatio` 2.625**: 쓸 수 있는 뷰포트에 해당 값이 없다.
- **한글 IME 실제 입력**: `event.code`가 같은 합성 이벤트로만 시험했다.
- **`]`, `[` 실제 키**: 도구가 `code`를 빈 값으로 보내 합성 이벤트로 대신했다.
- **Ctrl+S의 브라우저 저장 창**: `preventDefault`와 화면에 창이 없는 것은 확인했으나 일반 브라우저 창에서는 보지 않았다.
- **실제 파일 내려받기**: 저장소 밖 다운로드 폴더에 파일이 생기지 않도록 임시 `<a>`의 `click`을 막았다. Blob 생성, 파일 이름 지정, URL 생성까지는 실제 경로로 실행했다.
- **첫 페인트 깜빡임 육안 확인**: 인라인 스크립트가 스타일시트와 본문보다 앞에 있는 구조와 `data-theme` 적용 결과만 확인했다.
- **문제 1의 일반 창 재현**: 폭 768px 미만의 최상위 뷰포트는 모바일 흉내로 스크롤바가 겹쳐 그려져, iframe으로 재현했다. 일부 iframe 시험은 렌더링 프레임이 0개라 결과에서 제외했다.
- **`setPointerCapture` 실패 시 격자 밖에서 손을 뗀 경우**: 코드상 획이 끝나지 않을 수 있으나(`ui.js:327-331`) 실제 포인터로 캡처가 실패하는 상황을 만들지 못했다.
