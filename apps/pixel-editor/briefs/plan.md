## 사용자 요청

- 16×16 격자에 도트를 찍어 그림을 그린다.
- 완성하면 PNG로 저장할 수 있다.
- 색상 팔레트가 있다.

## 기능 범위

요청된 기능을 중심으로 작게 설계한다. 그리기 도구로 쓰기 위해 꼭 필요한 다음 기능까지만 포함한다.

- 펜, 지우개
- 드래그로 이어 그리기. 빠르게 끌어도 칸이 건너뛰어지지 않게 한다.
- 전체 지우기, 되돌리기와 다시 실행
- 작업 중인 그림이 새로고침으로 사라지지 않게 브라우저에 저장

레이어, 애니메이션, 격자 크기 변경, 파일 불러오기, 채우기 같은 기능은 넣지 않는다. 더 넣는 것이 좋다고 판단되면 넣지 말고 11장에 제안으로만 적는다.

## 반드시 지킬 제약

- HTML, CSS, JavaScript만 사용한다. 외부 라이브러리는 쓰지 않는 것을 기본으로 한다.
- 앱은 `/apps/pixel-editor/` 안에서 자체 완결되어야 하고, 블로그의 CSS와 JS에 의존하지 않는다.
- 팔레트는 이 앱을 위해 새로 고른 색으로 구성한다. 특정 게임기나 판타지 콘솔의 공식 팔레트를 가져오지 않는다.
- 모바일에서 사용할 수 있어야 하고, 그리는 중 페이지가 스크롤되면 안 된다.
- 경로는 모두 상대 경로로 쓴다. 사이트는 `https://ktw3108-ux.github.io/my-blog/`처럼 하위 경로에서 서비스된다.

## spec.md에 담을 내용

짧고 구현자가 바로 쓸 수 있게 작성한다.

1. 개요: 앱 한 문단 설명
2. 기능의 정확한 정의
   - 격자 데이터 표현과 투명 칸의 의미
   - 펜과 지우개의 동작, 드래그 시 칸 사이를 잇는 방법
   - 되돌리기 단위(드래그 한 번이 한 단계인지), 기록 상한
   - 전체 지우기의 동작과 되돌릴 수 있는지 여부
3. 팔레트: 색 목록(이름과 hex), 개수, 현재 색 표시, 사용자 지정 색 선택 여부
4. PNG 저장: 출력 크기(원본 16×16인지 확대본인지, 선택지를 둘지), 투명 배경 처리, 확대 시 뭉개지지 않게 하는 방법, 파일 이름, 빈 그림일 때의 동작
5. 화면 구성: 모바일과 데스크톱 배치, 격자 표시, 투명 칸 표시(체커 무늬 등)
6. 입력과 접근성: 마우스, 터치(Pointer Events), 키보드로 칸을 옮겨 그리는 방법, 단축키, 포커스, 스크린 리더 안내, 터치 대상 44×44px 이상, `prefers-reduced-motion`
7. 디자인: 색상 변수, 라이트/다크 모드(블로그의 `theme` 저장값을 읽어 첫 페인트 전에 적용), 글꼴
8. 저장: `localStorage` 키 이름과 형식, `try/catch` 처리, 저장값이 잘못되었을 때의 동작
9. 파일 구조: `/apps/pixel-editor/` 안의 파일과 각 역할. 그리기 규칙과 PNG 변환 데이터 처리는 DOM 없이 시험할 수 있게 분리한다.
10. Build 범위와 Embed 범위 구분
    - Build는 `apps/pixel-editor/` 안의 파일만 만든다.
    - Embed는 기존 `<template id="app-cards">`에 카드를 추가한다. 카드가 2개가 될 때의 간격 등 필요한 수정과 대상 파일을 코드 확인 후 명시한다.
    - 미리보기는 `preview.svg` 또는 이미지로 한다.
11. 검증 체크리스트: Review 단계에서 확인할 항목(그리기, 지우기, 빠른 드래그, 되돌리기, 저장 후 복원, PNG의 실제 크기와 픽셀 값, 투명도, 375px 폭, 데스크톱 폭, 라이트/다크, 콘솔 오류, 하위 경로 동작, 그리는 중 스크롤 없음)
12. 사용자가 결정해야 할 점과 추가 기능 제안: 있으면 짧게 목록으로, 없으면 "없음"
