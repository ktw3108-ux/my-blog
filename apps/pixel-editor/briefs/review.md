## 수정 범위

- 작성할 파일은 `C:\Users\ktw31\Desktop\my-blog\apps\pixel-editor\review.md` 하나뿐이다.
- 앱 코드를 고치지 않는다. 문제를 찾으면 review.md에 기록만 한다. 수정은 다른 단계에서 한다.
- 블로그의 다른 파일을 고치지 않는다. git으로 저장소 상태를 바꾸지 않는다.
- 임시 시험 스크립트와 임시 서버 폴더는 프로젝트 폴더 밖에서 만들고 끝나면 지운다.
- `.claude/` 안의 권한 설정을 고치지 않는다. 명령이 거부되면 우회하지 말고 review.md에 기록한다.
- 시험하며 넣은 `localStorage` 값(`pixel-editor:state`, `theme`)은 끝날 때 지운다.

## 기준 문서

`apps/pixel-editor/spec.md` 전체. 특히 11장 검증 체크리스트의 "Embed 후"를 뺀 모든 항목을 하나씩 확인한다. Embed는 아직 하지 않았다.

## 확인 방법

- 서버가 `http://localhost:8000`에 켜져 있으면 그대로 쓰고, 없으면 `node server.js`로 켠다. 네가 켠 서버만 끝날 때 끈다.
- 내장 브라우저(`mcp__Claude_Browser__*`)로 `http://localhost:8000/apps/pixel-editor/`를 연다. 탭이 `data:` 주소나 파일 미리보기로 열려 있으면 그 결과는 쓰지 않고 실제 서버 주소로 이동한다.
- 규칙은 `editor.js`, `png.js`를 직접 불러와 시험한다.
- PNG는 실제 저장 경로에서 Blob을 잡아 다시 디코딩해 픽셀 값을 확인한다. `toRgba` 결과만으로 통과 처리하지 않는다.
- 실제로 그림을 그려 화면과 데이터가 일치하는지 본다. 그린 뒤 새로고침 복원도 본다.
- 375px 폭과 데스크톱 폭, 라이트와 다크 모드 모두에서 스크린샷으로 본다. 끝나면 뷰포트를 `desktop`으로 되돌린다.
- 콘솔 오류는 새 탭에서 처음 연 뒤의 기록으로 판단한다.

## 코드 검토

`editor.js`, `png.js`, `ui.js`, `index.html`, `style.css`를 읽고 다음을 본다.

- 실제 동작 오류, 경계 조건, 획 진행 중 상태가 어긋날 가능성(포인터 취소, 포커스 상실, 창 크기 변경)
- 칸 좌표 계산이 캔버스 실제 크기와 맞는지. 창 크기를 바꾼 뒤의 좌표 포함
- spec.md와 다른 점, spec.md에 없는 기능이 들어갔는지
- `innerHTML` 오용, 전역 변수, 하드코딩된 색상(`:root`와 `PALETTE` 밖)
- 코드 규칙: ES 모듈, `const`/`let`, 화살표 함수, 들여쓰기 2칸, 세미콜론, 작은따옴표, 한국어 주석
- `/`로 시작하는 절대 경로가 없는지

## review.md 형식

1. 결론: `통과` 또는 `수정 필요`
2. 문제 목록: 심각도(치명/중요/사소), 재현 방법, 파일과 줄, 제안. 없으면 "없음"
3. 체크리스트 결과: spec.md 11장의 항목마다 통과/실패/미확인과 근거 한 줄
4. 확인하지 못한 것과 그 이유

추측을 사실처럼 쓰지 않는다. 실제로 실행한 것만 통과로 적는다.
