# 픽셀 아트 에디터 계획서

## 1. 개요

16×16 격자에 12색 팔레트로 점을 찍어 그림을 그리고 PNG로 저장하는 미니 웹앱이다. 펜과 지우개, 드래그 이어 그리기, 전체 지우기, 되돌리기와 다시 실행을 제공하고, 작업 중인 그림은 브라우저에 자동 저장되어 새로고침해도 남는다. 마우스, 터치, 키보드로 모두 그릴 수 있다. 외부 라이브러리 없이 `/apps/pixel-editor/` 안에서 자체 완결된다.

## 2. 기능 정의

수치는 모두 `editor.js` 상단 상수로 모은다.

| 상수 | 값 |
| --- | --- |
| `SIZE` | 16 |
| `MAX_HISTORY` | 100 |

### 2.1 격자 데이터

- 그림은 길이 256의 `Uint8Array` 하나다. 칸의 인덱스는 `y * 16 + x`이고 `(0, 0)`이 왼쪽 위다.
- 칸의 값은 `0`이 투명(칠하지 않은 칸), `1`~`12`가 `PALETTE[값 - 1]`이다.
- 투명은 색이 아니라 "아무것도 없음"이다. 화면에서는 체커 무늬로, PNG에서는 알파 0으로 나타난다. 팔레트의 흰색 계열(`종이`)과는 다른 값이다.

### 2.2 펜과 지우개

- 펜은 칸 값을 현재 색으로, 지우개는 `0`으로 바꾼다. 둘의 차이는 쓰는 값뿐이다.
- 시작 도구는 펜이다. 팔레트에서 색을 고르면 지우개 상태여도 펜으로 바뀐다.

### 2.3 드래그 이어 그리기

- 포인터 좌표를 칸 좌표로 바꾼다. `x = floor((clientX - rect.left) / rect.width * 16)`, `y`도 같다. 격자 밖이면 값이 범위를 벗어나는데 그대로 둔다.
- `pointermove`마다 `getCoalescedEvents()`가 있으면 각 이벤트를, 없으면 이벤트 자체를 순서대로 처리한다.
- 직전 칸과 새 칸을 **Bresenham 직선**으로 잇고, 양 끝을 포함한 경로의 모든 칸을 칠한다. 범위 밖 칸은 칠하지 않고 건너뛴다. 직전 칸도 범위 밖 좌표 그대로 기억하므로 격자 밖으로 나갔다 들어와도 경계까지 자연스럽게 이어진다.
- 새 칸이 직전 칸과 같으면 아무것도 하지 않는다.

### 2.4 되돌리기와 다시 실행

- **한 획이 한 단계다.** 획은 `pointerdown`부터 `pointerup` 또는 `pointercancel`까지다. `pointercancel`이면 그때까지 칠한 내용을 유지하고 획을 끝낸다.
- 키보드는 Space/Enter 한 번이 한 단계, Shift를 누른 채 이동한 구간 전체가 한 단계다(6장).
- 획 시작 전의 그림을 사본으로 보관한다. 획이 끝났을 때 그림이 시작 전과 같으면 기록하지 않고 다시 실행 기록도 유지한다.
- 그림이 바뀐 새 작업이 기록되면 다시 실행 기록을 비운다.
- 기록은 최대 100단계이고 넘으면 가장 오래된 것부터 버린다.
- 기록은 메모리에만 둔다. 새로고침하면 그림은 남고 기록은 사라진다.
- 획이 진행 중일 때 들어온 되돌리기, 다시 실행, 전체 지우기, 도구 변경은 무시한다.

### 2.5 전체 지우기

- 모든 칸을 `0`으로 만든다. 확인 창 없이 바로 실행한다.
- 되돌리기 한 단계로 복구할 수 있다.
- 이미 빈 그림이면 아무 일도 일어나지 않고 기록도 쌓이지 않는다.

## 3. 팔레트

이 앱을 위해 새로 고른 12색이다. 표의 순서가 값 `1`~`12`이자 화면 순서다(6열 2줄).

| 값 | 이름 | hex | | 값 | 이름 | hex |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 먹 | `#1c1b22` | | 7 | 주황 | `#f08a3c` |
| 2 | 회색 | `#8b90a0` | | 8 | 노랑 | `#f7c948` |
| 3 | 종이 | `#f7f5ee` | | 9 | 풀 | `#2f8a55` |
| 4 | 밤색 | `#8a5a3c` | | 10 | 하늘 | `#3fb6d3` |
| 5 | 빨강 | `#d6453d` | | 11 | 바다 | `#2a5caa` |
| 6 | 분홍 | `#e77fa8` | | 12 | 보라 | `#8e6bd8` |

- 12색으로 정한 이유: 44px 터치 대상 6열이 320px 폭(콘텐츠 288px)에도 들어가고, 2줄이면 모바일에서 격자 바로 아래에 전부 보인다.
- 시작 색은 `먹`이다.
- **현재 색 표시**: 도구 줄에 색 견본과 이름을 함께 보여 준다. 예: `현재 색 빨강`. 지우개일 때는 `지우개 사용 중`으로 바꾼다.
- 선택된 색은 색이 아니라 모양으로도 구분되게 `--text` 색의 3px 외곽선(간격 2px)을 준다.
- 모든 견본에 1px `--text-muted` 테두리를 둔다. 먹과 종이가 배경에 묻히지 않게 하기 위해서다.
- **사용자 지정 색은 넣지 않는다.** 요청 범위를 넘고, 넣으면 데이터 형식이 팔레트 인덱스로 끝나지 않는다. 12장에 제안으로 적었다.

## 4. PNG 저장

- **출력 크기**: 선택지 2개. `<select>`로 고르며 기본값은 320×320이다. 선택값은 저장한다(8장).
  - `320×320 (20배 확대)`, 값 `20`: 일반 뷰어와 메신저에서 바로 보기 좋다.
  - `16×16 (원본)`, 값 `1`: 게임 등 다른 도구의 소스용.
- **뭉개짐 방지**: `drawImage`나 CSS 확대를 쓰지 않는다. `toRgba`가 한 칸을 `scale × scale` 픽셀로 직접 복제한 RGBA 배열을 만들고, `canvas.width = 16 * scale`인 화면 밖 캔버스에 `putImageData`로 그대로 쓴다. 보간이 일어날 단계가 없다.
- **투명 배경**: 값 `0`은 RGBA `(0, 0, 0, 0)`, 나머지는 해당 색의 RGB와 알파 255다. 배경을 채우지 않는다. 격자선과 체커 무늬는 화면 전용이며 PNG에 들어가지 않는다.
- **파일 이름**: `pixel-art-YYYYMMDD-HHmmss-크기.png`, 사용자 현지 시각. 예: `pixel-art-20261109-153012-320x320.png`.
- **내려받기**: `canvas.toBlob(cb, 'image/png')` → `URL.createObjectURL` → `download` 속성을 준 임시 `<a>`를 클릭 → 1초 뒤 URL 해제. 완료되면 상태 줄에 `PNG로 저장했어요`를 보여 준다.
- **빈 그림**: 버튼은 비활성화하지 않는다. 눌렀을 때 내려받지 않고 상태 줄에 `빈 그림은 저장할 수 없어요. 먼저 점을 찍어 주세요.`를 보여 준다.
- `toBlob` 결과가 `null`이거나 예외가 나면 상태 줄에 `PNG를 만들지 못했어요`를 보여 준다.

## 5. 화면 구성

**모바일(기본)**, 위에서 아래 순서로:

1. 상단 줄: 앱 이름, `← 블로그로` 링크(`../../`)
2. 격자(폭 전체, 정사각형)
3. 도구 줄: 펜, 지우개, 현재 색 표시
4. 팔레트 6열 2줄(한 칸 높이 44px, 폭은 `1fr`, 간격 4px)
5. 작업 줄: 되돌리기, 다시 실행, 전체 지우기
6. 저장 줄: 크기 선택, `PNG 저장` 버튼
7. 상태 줄(`role="status"`)과 조작 안내 한 줄

**데스크톱(`min-width: 768px`)**: 2단 구성. 왼쪽에 격자, 오른쪽 `20rem` 세로 패널에 3~7번을 쌓는다. 격자 폭은 `min(100%, 32rem, calc(100dvh - 8rem))`로 짧은 화면에서도 한 번에 보이게 한다.

**격자 표시**: `<canvas>` 하나로 그린다. DOM 칸 256개를 쓰지 않는다.

- 격자를 감싸는 요소를 `ResizeObserver`와 창 `resize` 이벤트로 재서 `n = max(1, floor(폭 × devicePixelRatio / 16))`를 구하고, `canvas.width = canvas.height = n * 16`, CSS 크기는 `n * 16 / devicePixelRatio`px로 둔다. 칸이 물리 픽셀 정수 배가 되어 선이 흐려지지 않는다.
- 그리는 순서: 칸마다 투명이면 체커, 아니면 색 → 격자선 → 키보드 커서.
- **투명 칸**: 칸 하나를 2×2로 나눈 `--checker-a`/`--checker-b` 무늬. 칸 단위가 아니라 칸 안의 무늬이므로 어떤 색으로 칠한 칸과도 무늬 유무로 구분된다.
- **격자선**: 칸 왼쪽과 위쪽에 물리 1px, 마지막 줄의 오른쪽과 아래쪽은 캔버스 테두리로 대신한다.
- 캔버스에 쓰는 테마 색은 `getComputedStyle`로 읽고, `prefers-color-scheme` 변경 시 다시 읽어 그린다.

## 6. 입력과 접근성

**포인터(마우스, 터치, 펜)**: 캔버스에 Pointer Events를 쓴다.

- `pointerdown`에서 `isPrimary`이고 `button === 0`일 때만 획을 시작하고 `setPointerCapture`를 호출한다. 진행 중에는 다른 포인터를 무시한다.
- 획을 끝내는 이벤트: `pointerup`, `pointercancel`, `lostpointercapture`. 중복 호출에 안전해야 한다.
- 캔버스를 누르면 `focus({ preventScroll: true })`로 포커스를 준다.

**그리는 중 스크롤 방지**: 캔버스에 `touch-action: none`, `user-select: none`, `-webkit-touch-callout: none`, `html, body`에 `overscroll-behavior: none`을 준다. 캔버스의 `contextmenu`는 막는다(길게 누르기 메뉴 방지). 캔버스 바깥은 평소처럼 스크롤된다.

**키보드**: 캔버스에 포커스가 있을 때 동작한다.

| 키 | 동작 |
| --- | --- |
| 방향키 | 커서를 한 칸 이동. 가장자리에서 멈춤. 페이지 스크롤은 `preventDefault`로 막음 |
| Space, Enter | 커서 칸에 현재 도구 적용 |
| Shift + 방향키 | 이동하며 칠함. 첫 입력 때 시작 칸도 칠하고, Shift를 떼거나 포커스를 잃으면 획 종료 |
| P / E | 펜 / 지우개 |
| `[` / `]` | 이전 / 다음 색. 끝에서 반대쪽으로 순환 |

문서 전체에서 동작하는 단축키:

| 키 | 동작 |
| --- | --- |
| Ctrl/Cmd + Z | 되돌리기 |
| Ctrl/Cmd + Shift + Z, Ctrl/Cmd + Y | 다시 실행 |
| Ctrl/Cmd + S | PNG 저장(브라우저 저장 창 대신) |

- 키 판정은 `event.code`로 한다(`KeyP`, `KeyE`, `KeyZ`, `KeyY`, `KeyS`, `BracketLeft`, `BracketRight`). 한글 입력 상태에서도 동작하게 하기 위해서다.
- 글자 하나짜리 단축키는 캔버스 포커스 때만 동작시켜 화면 낭독기 단축키와 충돌하지 않게 한다.
- 처리한 단축키만 `preventDefault`한다. 그 외 Ctrl/Alt/Meta 조합은 건드리지 않는다.
- 되돌리기와 다시 실행은 키 반복을 허용하고, 칠하기(Space/Enter)는 `event.repeat`를 무시한다.

**포커스**

- 탭 순서는 DOM 순서: 블로그 링크 → 캔버스 → 도구 → 팔레트 → 작업 → 저장.
- 모든 조작 요소에 `:focus-visible` 외곽선을 준다.
- 키보드 커서는 마지막 입력이 키보드이고 캔버스에 포커스가 있을 때만 그린다. 커서는 `--cursor-outer`, `--cursor-inner` 두 겹 외곽선이라 어떤 칸 색 위에서도 보인다.
- 되돌리기와 다시 실행은 실행할 수 없을 때 `disabled` 대신 `aria-disabled="true"`와 흐린 스타일을 쓴다. 누르고 있던 버튼의 포커스를 잃지 않기 위해서다.

**화면 낭독기**

- 캔버스는 `tabindex="0"`, `role="application"`, `aria-label="16×16 그림판"`, `aria-describedby`로 조작 안내를 연결한다.
- 도구와 팔레트는 각각 `<fieldset>`의 네이티브 `input type="radio"`(시각적으로 숨김)를 쓴다. 팔레트 라벨은 색 이름이다.
- 시각적으로 숨긴 `aria-live="polite"` 영역에 키보드 입력 결과를 알린다. 예: `3행 5열, 빈 칸`, `3행 5열, 빨강으로 칠함`, `3행 5열, 지움`, `되돌렸습니다`, `전체를 지웠습니다`. 포인터 드래그 중에는 알리지 않는다.
- 캔버스 안에 대체 문구를 넣고, `<noscript>` 안내를 둔다.

**터치 대상**: 버튼, 링크, 팔레트, 도구, 크기 선택은 모두 44×44px 이상이다. 격자는 그리기 표면 하나로 보아 칸 단위 기준을 적용하지 않는다.

**`prefers-reduced-motion: reduce`**: 앱의 애니메이션은 버튼 상태 전환(120ms)뿐이며, 이 설정에서는 `transition: none`으로 끈다.

## 7. 디자인

블로그 CSS에 의존하지 않고 `style.css`의 `:root`에 변수를 직접 정의한다. 중립색과 강조색은 블로그와 같은 값이다. 컴포넌트에는 색상을 직접 쓰지 않는다. 팔레트 색은 `editor.js`의 `PALETTE`가 유일한 출처이고 견본에는 JS로 `style.backgroundColor`를 준다.

| 변수 | 라이트 | 다크 |
| --- | --- | --- |
| `--bg` | `#ffffff` | `#15171c` |
| `--bg-soft` | `#f5f6f8` | `#1e2128` |
| `--text` | `#1d2127` | `#e4e6ea` |
| `--text-muted` | `#5c6570` | `#9aa3ae` |
| `--border` | `#e4e7eb` | `#2c3039` |
| `--accent` (포커스 겸용) | `#2457d6` | `#8ab4ff` |
| `--accent-fg` | `#ffffff` | `#15171c` |
| `--checker-a` | `#d3d7de` | `#2b2f38` |
| `--checker-b` | `#bfc4cd` | `#383d48` |
| `--grid-line` | `rgba(29, 33, 39, 0.22)` | `rgba(228, 230, 234, 0.18)` |
| `--cursor-outer` | `#000000` | `#000000` |
| `--cursor-inner` | `#ffffff` | `#ffffff` |

`--accent`와 `--accent-fg`, `--text-muted`와 배경의 명암비는 계산으로 라이트 5.47:1 이상, 다크 6.31:1 이상이다.

- **테마**: 블로그와 같은 세 벌 구조(`:root`, `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`, `:root[data-theme="dark"]`)로 쓴다. `<head>` 인라인 스크립트가 `localStorage`의 `theme`(`dark` 또는 `light`만 인정)을 `try/catch`로 읽어 첫 페인트 전에 `data-theme`을 적용한다. 앱에 토글은 두지 않는다.
- **글꼴**: 블로그와 같은 시스템 폰트 스택. `word-break: keep-all`.
- **레이아웃**: 좌우 여백 16px 이상, 가로 스크롤 없음. 선택된 도구는 `--accent` 배경과 `--accent-fg` 글자로 표시한다.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`, `<meta name="color-scheme" content="light dark">`를 넣는다.

## 8. 저장

| 키 | 용도 |
| --- | --- |
| `pixel-editor:state` | 작업 상태. 앱이 읽고 쓴다 |
| `theme` | 블로그의 테마 선택값. 앱은 읽기만 한다 |

`pixel-editor:state` 값은 JSON 문자열이다.

```json
{ "version": 1, "pixels": "00a3…(256자)", "color": 5, "exportScale": 20 }
```

- `pixels`: 칸 값을 `toString(36)`으로 한 글자씩 이은 256자 문자열(`0`~`9`, `a`~`c`).
- `color`: 현재 색 값 `1`~`12`. `exportScale`: `1` 또는 `20`.
- **쓰는 시점**: 획 종료, 되돌리기, 다시 실행, 전체 지우기, 색 변경, 크기 변경. 드래그 중에는 쓰지 않는다. 도구와 기록은 저장하지 않는다.
- 읽기와 쓰기는 모두 `try/catch`로 감싼다. 쓰기가 처음 실패하면 상태 줄에 `브라우저 저장을 쓸 수 없어 새로고침하면 그림이 사라져요`를 한 번만 보여 주고 메모리로 계속 동작한다.
- **잘못된 저장값**
  - JSON 파싱 실패, 객체가 아님, `version !== 1`, `pixels`가 `/^[0-9a-c]{256}$/`에 맞지 않음: 빈 그림과 기본값으로 시작한다. 오류를 띄우지 않는다.
  - `pixels`는 맞고 `color`나 `exportScale`만 잘못됨: 그림은 살리고 그 값만 기본값(`1`, `20`)으로 한다.
- 탭을 여러 개 열면 마지막에 쓴 탭이 이긴다. 탭 간 동기화는 하지 않는다.

## 9. 파일 구조

```
apps/pixel-editor/
├── index.html    # 화면 뼈대, 테마 인라인 스크립트
├── style.css     # 색상 변수와 전체 스타일
├── editor.js     # DOM 없는 그리기 규칙, 기록, 직렬화, PALETTE
├── png.js        # DOM 없는 PNG용 데이터 변환, 파일 이름
├── ui.js         # 캔버스 렌더링, 입력, 저장 입출력, 내려받기, 낭독 문구
├── preview.svg   # 블로그 카드용 미리보기
├── spec.md       # 이 문서
└── review.md     # Review 단계 산출물
```

`editor.js` 내보내기(`ed` 객체를 직접 변경한다):

- `SIZE`, `MAX_HISTORY`, `PALETTE`(`{ name, hex }` 12개 배열)
- `createEditor(pixels?)` → `ed` = `{ pixels, undoStack, redoStack, stroke }`
- `linePoints(x0, y0, x1, y1)` → `[{ x, y }]` (양 끝 포함)
- `beginStroke(ed, x, y, value)`, `extendStroke(ed, x, y)`, `endStroke(ed)` → `boolean`(그림이 바뀌어 기록되었는지)
- `undo(ed)`, `redo(ed)`, `clear(ed)` → `boolean`
- `canUndo(ed)`, `canRedo(ed)`, `isEmpty(pixels)`
- `serializePixels(pixels)` → `string`, `parsePixels(str)` → `Uint8Array | null`

`png.js` 내보내기:

- `toRgba(pixels, scale)` → `Uint8ClampedArray`, 길이 `(16 * scale)² * 4`
- `exportFileName(date, scale)` → `string`

코드 규칙은 ES 모듈, `const`/`let`, 화살표 함수, 들여쓰기 2칸, 세미콜론, 작은따옴표, 한국어 주석, 전역 변수 금지다. 경로는 `./style.css`, `./ui.js`처럼 모두 상대 경로로 쓰고 `/`로 시작하는 경로를 쓰지 않는다. 사용자 데이터는 `textContent`로 넣는다.

## 10. Build 범위와 Embed 범위

### Build

`apps/pixel-editor/` 안의 파일만 만든다(9장, `review.md` 제외). 블로그의 다른 파일은 건드리지 않는다. `preview.svg`도 Build에서 만든다.

`preview.svg`: `viewBox="0 0 16 16"`, `width`와 `height` 160, `shape-rendering="crispEdges"`. 팔레트 색으로 그린 오리지널 도트 그림 하나(예: 작은 화분)를 `<rect>`로 그린다. `<img>` 안의 SVG는 `data-theme`을 받지 못하므로 라이트/다크 어디서나 읽히는 고정 배경색을 깐다. 카드에서는 96px로 보이며 칸당 6px이 되어 정수 배로 표시된다.

### Embed

코드 확인 결과, `js/app.js`의 `renderList`가 `#app-cards` 템플릿 내용 전체를 복제하므로 **`js/app.js`는 수정이 필요 없다.**

현재 `.app-cards`에는 `margin-bottom`만 있어 카드가 2개가 되면 간격 없이 붙는다. 따라서 CSS 수정이 필요하다.

| 수정 파일 | 내용 |
| --- | --- |
| `index.html` | `<template id="app-cards">`의 `<section>` 안, 기존 카드 **뒤에** 새 카드 추가 |
| `css/style.css` | `.app-cards`에 `display: grid`와 `gap` 추가, 기존 `@media (min-width: 640px)` 블록에 2열 추가 |

```html
<a class="app-card" href="apps/pixel-editor/">
  <img src="apps/pixel-editor/preview.svg" width="160" height="160" alt="16×16 격자에 점으로 그린 그림" loading="lazy">
  <span class="app-card-body">
    <strong>픽셀 아트 에디터</strong>
    <span>16×16 격자에 도트를 찍어 PNG로 저장하는 그림판</span>
  </span>
</a>
```

```css
.app-cards {
  display: grid;
  gap: 0.75rem;
  margin-bottom: 2rem;
}

/* 기존 @media (min-width: 640px) 블록 안 */
.app-cards {
  grid-template-columns: 1fr 1fr;
}
```

- 링크는 끝의 `/`를 유지한다. 없으면 앱의 상대 경로가 깨진다.
- 미리보기는 `preview.svg` 이미지로 한다.
- Embed 후 깃 커밋한다.

## 11. 검증 체크리스트

`node server.js` 후 `http://localhost:8000/apps/pixel-editor/`에서 확인한다. 규칙 시험은 콘솔에서 `await import('./editor.js')`, `await import('./png.js')`로 실행한다.

**그리기**

- [ ] 클릭과 탭 한 번으로 정확히 그 칸만 칠해진다. 네 귀퉁이 칸도 칠해진다
- [ ] 지우개로 칠한 칸이 투명(체커 무늬)으로 돌아온다
- [ ] 12색 모두 표의 hex로 칠해지고, 색을 고르면 펜으로 바뀌며 현재 색 표시가 갱신된다
- [ ] `linePoints(0,0,15,15)`가 16칸, `linePoints(0,0,15,3)`이 `x`마다 1칸씩 16칸이고 양 끝을 포함한다
- [ ] **빠른 드래그**: `pointermove`를 띄엄띄엄 합성해도(예: `(0,0)` → `(15,9)`) 끊긴 칸이 없다
- [ ] 격자 밖으로 나갔다 들어와도 오류 없이 이어지고, 범위 밖 인덱스가 쓰이지 않는다
- [ ] 두 번째 손가락과 마우스 오른쪽 버튼으로는 그려지지 않는다

**기록**

- [ ] 드래그 한 번이 되돌리기 한 단계다
- [ ] 다시 실행이 동작하고, 새 획을 그리면 다시 실행 기록이 비워진다
- [ ] 그림이 안 바뀐 획은 기록되지 않는다
- [ ] 101단계를 쌓으면 기록이 100개로 유지된다
- [ ] 전체 지우기를 되돌리면 복구된다. 빈 그림에서 전체 지우기를 해도 기록이 늘지 않는다

**저장과 복원**

- [ ] 그린 뒤 새로고침하면 그림, 현재 색, PNG 크기 선택이 복원된다
- [ ] 되돌리기, 전체 지우기 뒤 새로고침해도 그 결과가 유지된다
- [ ] `localStorage` 사용 불가 상태에서 오류 없이 동작하고 안내가 한 번 나온다
- [ ] 잘못된 JSON, `version` 불일치, 길이나 글자가 틀린 `pixels`이면 빈 그림으로 시작하고 콘솔 오류가 없다
- [ ] `color`만 잘못되면 그림은 유지된다

**PNG**

`URL.createObjectURL`을 감싸 Blob을 잡아 검사한다.

- [ ] 파일 형식이 PNG이고 IHDR의 폭·높이가 선택과 같다(16×16, 320×320)
- [ ] `toRgba` 길이가 `(16 * scale)² * 4`다
- [ ] 저장본을 다시 디코딩한 픽셀 값이 팔레트 RGB와 정확히 같다
- [ ] 투명 칸의 알파가 0이고, 칠한 칸의 알파가 255다
- [ ] 320×320에서 칸마다 20×20 전체가 같은 값이다(뭉개짐 없음)
- [ ] 격자선과 체커 무늬가 PNG에 없다
- [ ] 파일 이름이 형식에 맞다
- [ ] 빈 그림이면 내려받지 않고 안내가 나온다

**입력과 접근성**

- [ ] 375px 터치 에뮬레이션에서 드래그로 그려지고, **그리는 중 페이지가 스크롤되지 않는다**(`scrollY` 불변, 길게 눌러도 메뉴 없음)
- [ ] 격자 바깥에서는 페이지가 스크롤된다
- [ ] 방향키, Space, Enter, Shift+방향키로 그릴 수 있고 Shift 구간이 한 단계다
- [ ] P, E, `[`, `]`, Ctrl/Cmd 단축키가 동작하고 한글 입력 상태에서도 동작한다. Ctrl+S에서 브라우저 저장 창이 뜨지 않는다
- [ ] `aria-live` 문구가 맞고, Tab 순서와 포커스 표시가 정상이다
- [ ] 버튼, 링크, 팔레트, 도구, 크기 선택이 44×44px 이상이다(320px, 375px 폭 포함)
- [ ] `prefers-reduced-motion`에서 전환 효과가 없다

**화면**

- [ ] 375px과 데스크톱 폭에서 레이아웃이 맞고 가로 스크롤이 없다
- [ ] 칸 경계가 흐리지 않다(devicePixelRatio 1, 2, 2.625)
- [ ] 창 크기를 바꿔도 격자가 정사각형을 유지하고 좌표가 어긋나지 않는다
- [ ] 라이트/다크, 블로그에서 고른 `theme` 값이 모두 적용되고 첫 페인트 깜빡임이 없다. 캔버스 색도 테마를 따른다
- [ ] 브라우저 콘솔에 오류가 없다

**제약**

- [ ] 외부 요청이 없고 블로그의 CSS/JS를 불러오지 않는다
- [ ] `/`로 시작하는 절대 경로가 없다
- [ ] **하위 경로**: 저장소 상위 폴더를 문서 루트로 하는 임시 서버에서 `/my-blog/apps/pixel-editor/`가 정상 동작하고 404가 없다. `← 블로그로`가 `/my-blog/`로 간다
- [ ] 레이어, 애니메이션, 격자 크기 변경, 파일 불러오기, 채우기가 들어가지 않았다
- [ ] 팔레트가 3장의 표와 일치한다

**Embed 후**

- [ ] `#/`에 카드 2개가 간격을 두고 보이고, 375px에서 1열, 640px 이상에서 2열이다
- [ ] 기존 작은 숲 카드의 모양과 링크가 그대로다
- [ ] 태그 화면과 글 상세에는 카드가 보이지 않고, 라우트를 오가도 사라지거나 중복되지 않는다
- [ ] 카드에서 앱으로, 앱에서 블로그로 이동된다
- [ ] 라이트/다크 모두에서 미리보기가 읽힌다

## 12. 사용자가 결정해야 할 점과 추가 기능 제안

**결정해야 할 점**: 없음. 아래 기본값으로 진행하며, 다르게 원하면 승인 때 알려 주면 된다.

- 팔레트 12색, 사용자 지정 색 없음
- PNG 크기 선택지 16×16과 320×320, 기본 320×320
- 전체 지우기는 확인 창 없이 실행(되돌리기 가능)

**추가 기능 제안**(이번 범위에는 넣지 않음)

- 사용자 지정 색 선택
- 스포이트(칸의 색 집어 오기)
- 좌우 대칭 그리기
- 채우기
- 되돌리기 기록의 새로고침 후 유지
