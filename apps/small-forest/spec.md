# 작은 숲 키우기 계획서

## 1. 개요

5×5 숲터에서 타일을 네 방향으로 밀어 같은 단계끼리 합치는 오리지널 퍼즐이다. 타일은 씨앗(1) → 새싹(2) → 묘목(3) → 나무(4) → 숲(5)으로 자란다. 8번 움직일 때마다 돌이 하나 떨어져 칸을 막고, 돌 바로 옆에서 합치기를 하면 돌이 부서진다. 승리 조건 없이 움직일 수 없을 때까지 이어 가며 최고 점수를 노린다.

## 2. 규칙

수치는 모두 `game.js` 상단의 상수 객체 하나에 모은다.

| 상수 | 값 |
| --- | --- |
| 보드 크기 | 5×5 |
| 시작 타일 | 씨앗 3개 (무작위 빈 칸), 돌 없음 |
| 새 타일 확률 | 씨앗 90%, 새싹 10% |
| 돌 주기 | 유효 이동 8번마다 1개 |

### 2.1 이동과 합치기

입력 방향의 벽 쪽을 "앞"이라 한다. 줄(가로 또는 세로)마다 다음을 수행한다.

1. 돌을 경계로 줄을 구간으로 나눈다. 돌 너머로는 이동도 합치기도 할 수 없다.
2. 구간의 타일을 앞쪽부터 순서대로 본다. 빈 칸은 무시한다.
3. 현재 타일과 다음 타일의 단계가 같으면 합쳐서 한 단계 높은 타일 하나를 만들고 두 타일을 모두 소비한다. 다르면 현재 타일만 내려놓고 다음 타일로 넘어간다.
4. 결과를 구간의 앞쪽 칸부터 빈틈없이 채운다.

- 타일 하나는 한 번의 이동에서 **최대 1번** 합쳐진다. 합쳐서 나온 타일은 그 이동에서 다시 합쳐지지 않는다.
- 한 번의 이동에서 합쳐지는 쌍의 수에는 제한이 없다(줄이 달라도, 구간이 달라도 된다).
- **유효 이동**: 타일 위치가 하나라도 바뀌거나 합치기가 하나라도 일어난 이동. 유효하지 않은 입력은 아무 일도 일으키지 않는다(새 타일, 돌 카운트 모두 없음).

왼쪽 이동 예시(`.` 빈 칸, `#` 돌, 숫자 단계). Review는 이 표를 그대로 시험한다.

| 이동 전 | 이동 후 | 비고 |
| --- | --- | --- |
| `1 1 1 . .` | `2 1 . . .` | 앞쪽 쌍 우선 |
| `1 1 1 1 .` | `2 2 . . .` | 두 쌍, 연쇄 합치기 없음 |
| `2 1 1 . .` | `2 2 . . .` | 만들어진 2는 앞의 2와 합쳐지지 않음 |
| `5 5 3 . .` | `5 3 . . .` | 숲끼리 합치기 |
| `1 . # 1 .` | `1 . # 1 .` | 돌 너머로 합쳐지지 않음, 변화 없음 |
| `. 1 # 1 1` | `1 . . 2 .` | 3번째 칸 돌이 4번째 칸 합치기로 부서짐 |

### 2.2 유효 이동 후 처리 순서

1. 슬라이드와 합치기를 계산한다.
2. 돌을 부순다(2.5).
3. 점수를 더한다(3장).
4. 빈 칸 중 무작위 한 칸에 새 타일을 놓는다. 유효 이동 뒤에는 빈 칸이 항상 1개 이상이다.
5. 돌 카운트를 1 줄이고, 0이면 돌을 떨어뜨린다(2.4).
6. 게임 종료를 판정한다(2.6).

### 2.3 숲끼리 만났을 때

숲(5)이 최고 단계다. 숲 둘이 만나면 일반 합치기와 똑같이 처리하되 결과는 숲 하나다. 500점을 얻고 칸이 하나 비며, 돌 파괴도 일어난다. 6단계는 없다.

### 2.4 돌

- 카운트는 8에서 시작해 유효 이동마다 1씩 줄고, 0이 되면 돌 1개가 떨어진 뒤 8로 돌아간다.
- 위치: 네 귀퉁이를 뺀 빈 칸 중 무작위. 그런 칸이 없으면 귀퉁이 빈 칸 중 무작위.
- 빈 칸이 전혀 없으면 카운트를 0으로 둔 채 미루고, 다음 유효 이동의 5단계에서 다시 시도한다.
- 돌은 움직이지 않고, 합쳐지지 않으며, 타일이 통과할 수 없다. 보드 위 돌 개수에 상한은 없다.

### 2.5 돌 부수기

- 합치기 결과 타일의 **최종 칸**과 상하좌우로 맞닿은 돌이 부서진다. 대각선은 해당하지 않는다.
- 합치기 단계와 무관하며, 합치기 한 번으로 돌 여러 개가 함께 부서질 수 있다.
- 부서지는 시점은 슬라이드가 끝난 뒤다. 같은 이동의 다른 타일은 그 빈자리로 들어가지 않지만, 4단계의 새 타일은 들어갈 수 있다.

### 2.6 종료와 목표

- 끝없는 진행이며 승리 조건은 없다. 숲을 처음 만들면 안내 문구만 잠깐 보여 주고 게임은 멈추지 않는다.
- 네 방향 모두 유효 이동이 불가능하면 게임이 끝난다. 돌에 둘러싸인 빈 칸이 남아 있어도 끝날 수 있다.

## 3. 점수

| 합치기 | 기본 점수 |
| --- | --- |
| 씨앗 + 씨앗 → 새싹 | 10 |
| 새싹 + 새싹 → 묘목 | 30 |
| 묘목 + 묘목 → 나무 | 80 |
| 나무 + 나무 → 숲 | 200 |
| 숲 + 숲 → 숲 | 500 |

- 연속 보너스는 **한 번의 이동**에서 합쳐진 쌍의 수 `k`로 정한다. 이동을 이어서 해도 누적되지 않는다.
- 배율 = `min(3, 1 + 0.5 × (k − 1))` (1쌍 ×1, 2쌍 ×1.5, 3쌍 ×2, 4쌍 ×2.5, 5쌍 이상 ×3)
- 획득 점수 = 이번 이동 기본 점수 합 × 배율. 보너스 표시값 = 획득 점수 − 기본 점수 합.
- 예: 씨앗 쌍 + 새싹 쌍은 `(10 + 30) × 1.5 = 60`, 보너스 20. 돌 파괴 자체에는 점수가 없다.

## 4. 화면 구성

기존 퍼즐류의 "왼쪽 위 제목, 오른쪽 위 점수 상자, 그 아래 보드" 배치를 쓰지 않는다.

**모바일(기본)**, 위에서 아래 순서로:

1. 상단 줄: 앱 이름, `← 블로그로` 링크(`../../`)
2. 보드(폭 전체, 정사각형)와 그 위에 겹치는 게임 오버 표시
3. 점수 띠: 현재 점수, 최고 기록, 연속 보너스(직전 이동. 예 `×1.5 +20`, 1쌍 이하이면 `-`)
4. 돌 카운트: `다음 돌까지 N번` 문구와 8칸 눈금. 미뤄진 상태면 `돌이 곧 떨어져요`
5. 방향 버튼 한 줄(← ↑ ↓ →), 새 게임 버튼, 보드 읽기 버튼
6. 성장 단계 범례(1~5 그림과 이름)와 조작 안내 한 줄

**데스크톱(`min-width: 768px`)**: 2단 구성. 왼쪽 보드(최대 `30rem`), 오른쪽 세로 패널에 3~6번을 쌓는다.

**게임 오버 표시**: 보드 위 반투명 덮개에 `더 자랄 자리가 없어요`, 최종 점수, 신기록이면 `새 최고 기록`, 새 게임 버튼. 이후 이동 입력은 무시한다.

**새 게임**은 확인 없이 바로 시작한다. 최고 기록은 갱신 즉시 저장되므로 잃지 않는다.

## 5. 입력과 접근성

- **방향키**: `document`의 `keydown`에서 처리하고 화살표 키에만 `preventDefault`를 호출한다. `event.repeat`와 Ctrl/Alt/Meta 조합은 무시한다.
- **스와이프**: 보드에 Pointer Events를 쓴다. 주 포인터만 추적하고 `setPointerCapture`를 호출한다. `pointerup` 때 이동 거리가 24px 이상이면 더 큰 축의 방향으로 1회 이동한다. `pointercancel`은 무시한다.
- **스크롤 방지**: 보드에 `touch-action: none`, `html, body`에 `overscroll-behavior: none`을 준다. 보드 바깥은 평소처럼 스크롤된다.
- **방향 버튼**: 스와이프의 단일 포인터 대안이자 화면 낭독기 사용자의 조작 수단이다.
- **애니메이션 중 입력**: 다음 입력 1개만 보관했다가 애니메이션이 끝나면 처리한다.
- **키보드 포커스**: 모든 버튼과 링크에 `:focus-visible` 외곽선을 준다. 게임 오버가 되면 덮개의 새 게임 버튼으로 포커스를 옮긴다.
- **화면 낭독기**
  - 보드는 `role="group"`, `aria-label="숲터 5×5"`이고 타일 DOM은 `aria-hidden="true"`로 숨긴다.
  - 시각적으로 숨긴 `aria-live="polite"` 영역에 이동 결과를 알린다. 예: `왼쪽으로 이동. 합치기 2쌍, 60점. 돌 1개 부서짐. 다음 돌까지 3번.`
  - 유효하지 않은 이동은 `움직일 수 없는 방향입니다`, 게임 오버는 최종 점수를 알린다.
  - 보드 읽기 버튼은 현재 보드를 줄 단위로 같은 영역에 읽어 준다. 예: `1행: 씨앗, 빈 칸, 돌, 나무, 빈 칸.`
- **터치 대상**: 버튼과 링크는 모두 44×44px 이상.
- **`prefers-reduced-motion: reduce`**: 슬라이드, 합치기, 돌 낙하, 파괴 애니메이션을 모두 끄고 즉시 그린다. 입력 보관 대기도 없앤다.
- 기본 애니메이션: 슬라이드 120ms, 합치기·돌 낙하 150ms.

타일 배경과 글자의 명암비는 위 값으로 모두 4.5:1 이상임을 계산으로 확인했다.

- **테마 적용**: 블로그와 같은 세 벌 구조(`:root`, `@media (prefers-color-scheme: dark)`의 `:root:not([data-theme="light"])`, `:root[data-theme="dark"]`)로 쓴다. `<head>` 인라인 스크립트가 `localStorage`의 `theme`을 읽어 첫 페인트 전에 `data-theme`을 적용한다. 앱에 별도 토글은 두지 않고 블로그에서 고른 테마와 시스템 설정을 따른다.
- **글꼴**: 블로그와 같은 시스템 폰트 스택. `word-break: keep-all`.
- **레이아웃**: 좌우 여백 16px 이상, 가로 스크롤 없음. 보드 폭은 `min(100%, 30rem)`, `aspect-ratio: 1`.
- **타일 표현**: 왼쪽 위에 단계 숫자, 가운데에 그림을 함께 넣는다. 돌은 그림만 있고 숫자가 없으며, 색이 아니라 모양으로도 구분된다.
- **그림은 인라인 SVG를 쓴다.** 이유는 세 가지다.
  - 이모지는 OS마다 모양이 달라 단계 구분과 초록 톤을 보장할 수 없고, 씨앗에 딱 맞는 이모지도 없다.
  - `currentColor`로 `--stage-N-fg`를 받아 라이트/다크에 바로 맞출 수 있다.
  - 외부 파일이나 글꼴 없이 자체 완결된다.
- `index.html`에 `<symbol id="stage-1">`~`stage-5`, `stone`을 한 번 정의하고 타일에서 `<use>`로 재사용한다.

## 7. 저장

| 키 | 용도 |
| --- | --- |
| `small-forest:best` | 최고 점수(정수 문자열). 앱이 읽고 쓴다 |
| `theme` | 블로그의 테마 선택값. 앱은 읽기만 한다 |

- 읽기와 쓰기는 모두 `try/catch`로 감싼다. 실패하면 메모리 값으로 계속 동작한다.
- 값이 정수가 아니거나 음수이면 0으로 본다.
- 점수가 최고 기록을 넘는 순간 저장한다. 진행 중인 판은 저장하지 않아 새로고침하면 새 게임이 된다.

## 8. 파일 구조

```
apps/small-forest/
├── index.html    # 화면 뼈대, SVG 심볼, 테마 인라인 스크립트
├── style.css     # 색상 변수와 전체 스타일
├── game.js       # DOM 없는 순수 규칙 모듈
├── ui.js         # 렌더링, 입력, 애니메이션, 낭독 문구, 저장
├── preview.svg   # 블로그 카드용 미리보기
├── spec.md       # 이 문서
└── review.md     # Review 단계 산출물
```

`game.js`는 다음을 내보내 브라우저 콘솔에서 바로 시험할 수 있게 한다. 무작위는 `rng` 인자로 주입한다.

- `createGame(rng = Math.random)` → `state`
- `move(state, dir, rng = Math.random)` → `{ state, moved, pairs, gained, bonus, broken, spawned, droppedStone }` (입력 `state`는 변경하지 않음)
- `hasMoves(state)` → `boolean`
- `state` = `{ grid, score, stoneCountdown, over, nextId }`. `grid`는 5×5 2차원 배열이고 칸은 `null`, `{ id, kind: 'tile', level }`, `{ id, kind: 'stone' }` 중 하나다.

코드 규칙은 ES 모듈, `const`/`let`, 화살표 함수, 들여쓰기 2칸, 세미콜론, 작은따옴표, 한국어 주석, 전역 변수 금지, 경로는 모두 상대 경로다.

## 9. Build 범위와 Embed 범위

### Build

`apps/small-forest/` 안의 파일만 만든다(8장, `review.md` 제외). 블로그의 다른 파일은 건드리지 않는다.

### Embed

`js/app.js`의 `renderList`는 끝에서 `main.replaceChildren(header, content)`를 호출해 `<main>` 안을 통째로 바꾼다. 따라서 `index.html`의 `<main>` 안에 카드를 직접 넣으면 첫 렌더링에서 사라진다. `<main>` 바깥의 정적 요소로 두면 글 상세와 태그 화면에도 계속 보인다.

제안: 카드 마크업은 `index.html`의 `<template>`에 두고, `renderList`가 전체 목록(`#/`)일 때만 복제해 넣는다.

| 수정 파일 | 내용 |
| --- | --- |
| `index.html` | `</main>` 다음에 `<template id="app-cards">` 추가 |
| `js/app.js` | `renderList`에서 템플릿 복제 후 삽입 |
| `css/style.css` | `.app-cards`, `.app-card` 스타일 추가(기존 CSS 변수만 사용) |

```html
<template id="app-cards">
  <section class="app-cards" aria-label="미니 웹앱">
    <a class="app-card" href="apps/small-forest/">
```

- 링크는 끝의 `/`를 유지한다. 없으면 앱의 상대 경로가 깨진다.
- 미리보기는 iframe 대신 이미지를 쓴다. iframe은 메인 화면에서 게임을 실행하고 스와이프를 가로채기 때문이다. `<img>` 안의 SVG는 `data-theme`을 받지 못하므로 `preview.svg`는 라이트/다크 어디서나 읽히는 고정 색으로 그린다.
- 카드에는 제목, 설명, 미리보기를 넣고, Embed 후 커밋한다.

## 10. 검증 체크리스트

`node server.js` 후 `http://localhost:8000/apps/small-forest/`에서 확인한다. 규칙 시험은 콘솔에서 `await import('/apps/small-forest/game.js')`로 상태를 직접 만들어 실행한다.

**규칙**

- [ ] 2.1 예시 표 6행이 모두 표와 일치한다
- [ ] 네 방향이 모두 같은 규칙으로 동작한다
- [ ] 유효하지 않은 이동에서 타일, 돌 카운트, 점수가 변하지 않는다
- [ ] 시작 시 씨앗 3개, 돌 0개다
- [ ] 유효 이동마다 새 타일이 정확히 1개 나오고, `rng` 값 0.89/0.90 경계에서 씨앗/새싹이 갈린다
- [ ] 숲 + 숲이 숲 1개가 되고 500점이며 돌 파괴도 일어난다
- [ ] 돌이 8번째 유효 이동 뒤에 떨어지고, 이후 8번마다 반복된다
- [ ] 돌은 귀퉁이가 아닌 빈 칸 우선, 귀퉁이만 남으면 귀퉁이에 떨어진다
- [ ] 빈 칸이 없으면 돌이 미뤄지고 다음 유효 이동에서 떨어진다
- [ ] 돌이 움직이거나 합쳐지지 않고, 돌 너머로 이동하거나 합쳐지지 않는다
- [ ] 합치기 칸의 상하좌우 돌은 부서지고 대각선 돌은 남는다. 한 번에 여러 개도 부서진다
- [ ] 돌이 부서진 자리로 같은 이동의 타일이 들어가지 않는다

**점수**

- [ ] 단계별 점수 5종이 표와 일치한다
- [ ] 2쌍 ×1.5, 3쌍 ×2, 5쌍 이상 ×3이고 보너스 표시가 맞다

**게임 오버와 저장**

- [ ] 빈 칸 없이 합칠 쌍이 없을 때 끝난다
- [ ] 돌에 둘러싸인 빈 칸만 남고 움직일 수 없을 때도 끝난다
- [ ] 게임 오버 표시, 포커스 이동이 동작하고 이후 입력이 무시된다
- [ ] 새 게임 버튼이 판을 초기화하고 돌 카운트가 8로 돌아간다
- [ ] 최고 기록이 새로고침과 새 게임 후에도 유지된다
- [ ] `localStorage` 사용 불가 상태와 잘못된 저장값에서도 오류 없이 동작한다

**입력과 접근성**

- [ ] 방향키 입력 시 페이지가 스크롤되지 않는다
- [ ] 375px 터치 에뮬레이션에서 스와이프 네 방향이 동작하고 스와이프 중 페이지가 움직이지 않는다
- [ ] 방향 버튼, 보드 읽기가 동작하고 `aria-live` 문구가 맞다
- [ ] Tab 순서와 포커스 표시가 정상이다
- [ ] 버튼과 링크 크기가 44×44px 이상이다
- [ ] `prefers-reduced-motion`에서 애니메이션이 없다

**화면**

- [ ] 375px과 데스크톱 폭에서 레이아웃이 맞고 가로 스크롤이 없다
- [ ] 라이트/다크 모드, 블로그에서 고른 `theme` 값이 모두 적용되고 첫 페인트 깜빡임이 없다
- [ ] 브라우저 콘솔에 오류가 없다

**제약**

- [ ] 앱의 파일명, 코드, 화면 문구에 금지된 네 자리 숫자 `2048`이 없다(`spec.md`, `briefs/`, `review.md` 제외)
- [ ] 타일 표시가 1~5이고 두 배로 커지는 숫자 타일이 없다
- [ ] 베이지 계열 색, 4장에서 금지한 배치를 쓰지 않았다
- [ ] 외부 요청이 없고 블로그의 CSS/JS를 불러오지 않는다

**Embed 후**

- [ ] `#/`에 카드가 보이고 태그 화면과 글 상세에는 보이지 않는다
- [ ] 라우트를 오가도 카드가 사라지거나 중복되지 않는다
- [ ] 카드에서 앱으로, 앱에서 블로그로 이동된다
