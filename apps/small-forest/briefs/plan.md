## 만들 게임 (사용자 승인된 방향)

- 방향키로 타일을 밀어 합치는 오리지널 퍼즐이다. 모바일에서는 스와이프로 조작한다.
- 보드는 5×5 칸이다.
- 같은 단계의 타일이 만나면 씨앗 → 새싹 → 묘목 → 나무 → 숲으로 자란다. 타일에는 단계 숫자와 그림을 함께 표시한다.
- 고유 규칙: 일정 횟수마다 돌이 하나 떨어져 칸을 막고, 돌 옆에서 합치기를 하면 돌이 부서진다.
- 점수판: 현재 점수, 최고 기록(브라우저 저장), 한 번에 여러 쌍을 합칠 때의 연속 보너스.
- 디자인: 블로그의 초록색 톤, 라이트/다크 모드 지원.

## 반드시 지킬 제약

이 앱은 특정 기존 게임의 재현이 아니어야 한다.

- 이름, 화면 문구, 파일명, 코드 식별자에 "2048"을 쓰지 않는다.
- 2, 4, 8, 16처럼 두 배로 커지는 숫자 타일을 쓰지 않는다. 단계는 1, 2, 3처럼 표시한다.
- 4×4 보드, 베이지 계열 타일 색, 기존 게임의 레이아웃과 비슷한 화면 구성을 쓰지 않는다.
- HTML, CSS, JavaScript만 사용한다. 외부 라이브러리는 쓰지 않는 것을 기본으로 한다.
- 앱은 `/apps/small-forest/` 안에서 자체 완결되어야 하고, 블로그의 CSS와 JS에 의존하지 않는다.
- 모바일에서 사용할 수 있어야 하고, 스와이프 중 페이지가 스크롤되면 안 된다.

## spec.md에 담을 내용

짧고 구현자가 바로 쓸 수 있게 작성한다.

1. 개요: 게임 한 문단 설명
2. 규칙의 정확한 정의
   - 이동과 합치기 순서(한 번 이동에 타일이 몇 번 합쳐질 수 있는지 포함)
   - 새 타일이 나오는 규칙과 확률
   - 최고 단계인 숲끼리 만났을 때의 처리
   - 돌이 떨어지는 주기, 떨어지는 위치, 돌을 부수는 "옆"의 정의(상하좌우 여부), 돌이 이동하는지 여부
   - 게임 종료 조건과 목표(끝없는 진행인지, 승리 조건이 있는지)
3. 점수 계산: 단계별 점수와 연속 보너스 공식을 숫자로
4. 화면 구성: 점수판, 보드, 새 게임 버튼, 조작 안내, 게임 오버 표시
5. 입력과 접근성: 방향키, 스와이프, 키보드 포커스, 스크린 리더용 안내, 터치 대상 44×44px 이상, `prefers-reduced-motion`
6. 디자인: 색상 변수, 라이트/다크 모드, 단계별 타일 표현 방법(그림은 이모지 또는 인라인 SVG 중 선택하고 이유를 적는다)
7. 저장: `localStorage` 키 이름, `try/catch` 처리
8. 파일 구조: `/apps/small-forest/` 안의 파일과 각 역할
9. Build 범위와 Embed 범위 구분
   - 블로그 메인 화면은 `js/app.js`가 `<main>` 안을 다시 그린다. 카드가 사라지지 않게 넣는 방법을 코드 확인 후 제안한다.
   - Embed에서 수정할 파일을 명시한다.
10. 검증 체크리스트: Review 단계에서 확인할 항목(규칙별 동작, 게임 오버, 최고 기록 유지, 375px 폭, 데스크톱 폭, 라이트/다크, 콘솔 오류)
11. 사용자가 결정해야 할 점: 있으면 짧게 목록으로, 없으면 "없음"
